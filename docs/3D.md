# Modello 3D (sezione `#in-3d`)

- **File**: `src/assets/3d/acoustic_guitar.glb` (nome in `src/data/model3d.js`). Senza file la sezione non viene mostrata.
- **Origine**: «Acoustic Guitar» di afurokn, <https://sketchfab.com/3d-models/acoustic-guitar-b52fcec4b641493f8939c50c253c4ac3>, licenza **CC BY 4.0**. Download ufficiale da Sketchfab (formato GLB); niente estrazione dal viewer. L'attribuzione in pagina è obbligatoria (testata in `tests/unit/Model3DSection.spec.js`).
- **Ottimizzazione** (4,1 MB → 1,81 MB, 2026-10-24), dal GLB originale:

  ```bash
  npx --yes @gltf-transform/cli@4.5.1 optimize originale.glb acoustic_guitar.glb \
    --compress quantize --texture-compress webp --texture-size 2048 --simplify false --instance false
  ```

  `--simplify false` preserva corde e tasti. `--instance false` evita `EXT_mesh_gpu_instancing`: con le istanze il modello si vede, ma `<model-viewer>` scrive 9 errori in console (`Mesh is missing primitive index association`). Con le istanze il file sarebbe 1,05 MB.

- **Niente `--compress meshopt` né `draco`.** `<model-viewer>` non include i decoder: li scarica da una CDN esterna, che la CSP blocca. Con meshopt il modello non si carica (`THREE.GLTFLoader: setMeshoptDecoder must be called before loading compressed files`, successo il 2026-10-24). La quantizzazione (`KHR_mesh_quantization`) e le texture WebP sono lette da three.js senza decoder. Per ridurre molto il peso servirebbe ospitare il decoder meshopt nel sito (`meshoptDecoderLocation`) e rivedere la CSP.
- **Verifica obbligatoria** dopo ogni cambio di modello: aprire la pagina nel browser (build + `wrangler dev`) e controllare che la console non abbia errori e che `document.querySelector('model-viewer').loaded` sia `true`. La build e i test non lo rilevano.
- **Visualizzatore**: `@google/model-viewer` caricato a richiesta (`src/components/ui/GuitarViewer.vue`). CSP: vedi commento in `public/_headers`; l'hash dello `<style>` interno è verificato da `scripts/check-dist.mjs`.
